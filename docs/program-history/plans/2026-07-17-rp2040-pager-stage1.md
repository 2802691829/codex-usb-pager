# RP2040 Pager Stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and flash a Pico SDK firmware that receives the existing pager protocol over USB CDC and renders every pager state on the RP2040-Zero onboard WS2812 at no more than 8 percent brightness.

**Architecture:** Keep protocol parsing and LED effect sampling in SDK-independent C modules with native host tests. The RP2040 entry point owns non-blocking USB CDC input, the eight-second offline timeout, and a GP16 WS2812 PIO driver. Stage 1 uses one core and does not connect the display or buzzer.

**Tech Stack:** Raspberry Pi Pico SDK 2.2.0, C11/C++17, CMake, NMake, ARM GNU Toolchain 14.3, PIO, pico_stdio_usb, Python pytest

## Global Constraints

- Controller is RP2040-Zero with 2 MB flash; configure the SDK as `PICO_BOARD=pico`.
- WS2812 DIN is GP16 and no RGB channel may exceed 20 out of 255.
- USB transport is CDC serial and remains compatible with `STATE <state> RUN=<n> WAIT=<n> DONE=<n> BAL=<token> EV=<event>\n`.
- Host heartbeat is two seconds and firmware enters OFFLINE after eight seconds without a valid snapshot.
- No display or buzzer wiring is added in stage 1.
- Future reserved pins are GP29/GP28/GP27/GP26/GP15 for SCL/SDA/RES/DC/BLK and GP14 for the active-low buzzer module.

```c
static void test_led_effects(void) {
    pager_rgb_t idle = pager_led_sample(PAGER_IDLE, 0);
    pager_rgb_t run_a = pager_led_sample(PAGER_RUNNING, 0);
    pager_rgb_t run_b = pager_led_sample(PAGER_RUNNING, 900);
    pager_rgb_t wait_on = pager_led_sample(PAGER_WAIT, 40);
```

- Produces: `codex_pager_rp2040.uf2`, a USB CDC device, and WS2812 output on GP16.

- [ ] **Step 1: Add compile-time board constraints**

```c
#define PAGER_WS2812_PIN 16U
#define PAGER_BUZZER_PIN 14U
#define PAGER_DISPLAY_BLK_PIN 15U
#define PAGER_DISPLAY_DC_PIN 26U
#define PAGER_DISPLAY_RES_PIN 27U
#define PAGER_DISPLAY_SDA_PIN 28U

#define PAGER_OFFLINE_TIMEOUT_MS 8000U
#define PAGER_LINE_CAPACITY 96U
```

Add `_Static_assert(PAGER_WS2812_PIN == 16U, "RP2040-Zero WS2812 pin mismatch");` in `main.c`.

- [ ] **Step 2: Add the official-style WS2812 PIO program**

Use a four-instruction 800 kHz PIO program with side-set, generated by `pico_generate_pio_header`. Initialize one state machine on `pio0`, transmit GRB words, and never block longer than one LED word.

- [ ] **Step 3: Implement non-blocking USB CDC input**

Enable `pico_stdio_usb` and disable UART stdio. Poll `getchar_timeout_us(0)` in the main loop, accumulate at most 95 printable ASCII bytes, dispatch only on newline, reset the buffer after overflow, and update `last_valid_snapshot_ms` only when `pager_parse_line` succeeds.

- [ ] **Step 4: Integrate state and LED scheduling**

Initialize to OFFLINE, sample the current effect every 10 ms, reset `state_started_ms` when the selected state changes, and call `pager_apply_timeout` each loop. Sleep at most 1 ms so USB input remains responsive.

- [ ] **Step 5: Create the Pico SDK build target**

```cmake

    src/main.c src/pager_core.c src/led_effects.c)

    ${CMAKE_CURRENT_LIST_DIR}/src/ws2812.pio)
```
